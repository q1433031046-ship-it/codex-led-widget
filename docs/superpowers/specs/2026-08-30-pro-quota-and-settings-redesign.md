# Pro 额度识别与设置交互重构设计

## 状态

设计已获用户批准。默认产品方向是“主 Codex 优先”，右键交互采用“单层快捷菜单 + 独立设置页”。

## 背景与根因

应用通过 Codex App Server 的 `account/rateLimits/read` 读取 ChatGPT 额度。该接口可能同时返回：

- 向后兼容的单桶视图 `rateLimits`；
- 按 `limitId` 分组的多桶视图 `rateLimitsByLimitId`；
- 每个桶内可选的 `primary` 和 `secondary` 窗口；
- 每个窗口自身的 `windowDurationMins`、`usedPercent` 和 `resetsAt`。

当前代码固定选择 `rateLimitsByLimitId.codex`，并把 `primary` 无条件当作 5 小时窗口、`secondary` 无条件当作 7 天窗口。Pro 账户的主 `codex` 桶可能只返回一个 10080 分钟窗口且把它放在 `primary`，因此应用会把真实的 7 天额度错误标成 5 小时额度，同时把 7 天卡片显示为空。

同一账户还可能返回独立额度桶，例如：

- `codex`：主 Codex 额度，可能只有 10080 分钟窗口；
- `codex_bengalfox`：GPT-5.3-Codex-Spark，可能同时有 300 和 10080 分钟窗口；
- `base_model_inference`：其他服务端计量桶。

现有右键菜单包含三层以上原生子菜单。Electron 原生菜单在点击复选或单选项后会关闭，代码通过 90ms 延迟、鼠标坐标和重新 `popup` 的方式强制重开子菜单。这会造成闪动、错位、焦点变化和鼠标轻微移动后无法重开。

## 目标

1. 按服务端提供的窗口时长准确识别 5 小时和 7 天额度。
2. 默认展示主 `codex` 额度，不聚合或混合不同额度桶。
3. 允许用户在设置页切换到 Spark 等独立额度源。
4. 当当前额度源缺少某类窗口时，隐藏对应卡片且不伪造 `0%`。
5. 用单层快捷菜单取代多级原生菜单，把完整配置迁入独立设置页。
6. 保留现有用户设置和统计数据，避免升级时删除 AppData。
7. 为 Pro、多桶、未知窗口时长和额度源消失建立回归测试。

## 非目标

- 不把多个 `limitId` 的百分比合并成一个“总额度”。
- 不根据 Plus、Pro 或其他套餐倍率推算服务端没有返回的绝对上限。
- 不读取、显示或复制认证令牌、账户 ID 或本地认证文件。
- 不制作自绘右键浮层；复杂配置统一进入设置窗口。
- 不强行猜测和改写无法可靠归类的旧版历史记录。

## 额度数据模型

### 原始响应保留

`quota-service` 应先把所有可用桶归一化为 `sources`，再选择活动额度源。向后兼容的 `rateLimits` 仅在 `rateLimitsByLimitId` 缺失或没有可用桶时作为回退。

归一化后的顶层结构：

```js
{
  activeSourceId: "codex",
  sources: [
    {
      id: "codex",
      name: "主 Codex",
      rawName: null,
      planType: "prolite",
      windows: {
        shortTerm: null,
        weekly: {
          kind: "weekly",
          usedPercent: 8,
          remainingPercent: 92,
          windowDurationMins: 10080,
          resetsAt: "2026-09-06T02:33:48.000Z"
        },
        other: []
      },
      reachedType: null,
      credits: null
    }
  ],
  primary: null,
  secondary: {},
  fetchedAt: "2026-08-30T03:48:01.000Z"
}
```

`primary` 和 `secondary` 暂时保留为渲染层兼容字段，但它们由窗口分类结果生成：`primary` 指向 `shortTerm`，`secondary` 指向 `weekly`。字段位置不再参与窗口类型判断。

### 窗口分类

对每个额度桶，同时检查原始 `primary` 和 `secondary`：

- `windowDurationMins === 300`：归类为 `shortTerm`，用户文案为“5 小时额度”；
- `windowDurationMins === 10080`：归类为 `weekly`，用户文案为“7 天额度”；
- 其他有限正数：保留在 `other`，使用实际时长生成标签；
- 缺失、非数字或非正数：保留为未知窗口，不映射成 5 小时或 7 天。

`usedPercent` 直接采用服务端数值并限制到 0 至 100。`remainingPercent` 仅计算为 `100 - usedPercent`。缺失窗口保持 `null`，不能变成 `0%`。

### 额度源选择

设置中保存 `quotaSourceId`：

1. 默认值为 `codex`；
2. 如果已保存的额度源仍存在，继续使用；
3. 如果已保存额度源消失，回退到 `codex`；
4. 如果 `codex` 也不存在，选择第一个有效桶；
5. 回退发生时，在设置页显示一次非阻塞提示。

设置页列出服务端实际返回的额度源。主桶显示为“主 Codex”，有 `limitName` 的桶优先使用服务端名称；内部名称仅出现在诊断区。

### 仪表与卡片

- 活动源同时有 5 小时和 7 天窗口时，两张卡片均可显示。
- 活动源只有 7 天窗口时，5 小时卡片自动隐藏，主仪表自动使用 7 天剩余量。
- 活动源只有 5 小时窗口时，7 天卡片自动隐藏，主仪表使用 5 小时剩余量。
- 用户选择的仪表来源当前不可用时，按“5 小时、7 天、其他有效窗口”的顺序回退，并在设置页说明实际来源。
- 没有任何有效窗口时显示“额度暂不可用”，不得显示绿色 `100%` 或红色 `0%`。

`prolite` 等内部套餐值在主界面映射为可理解的“Pro”；原始值只进入脱敏诊断信息。

## 历史记录与迁移

新的额度历史以 `${limitId}:${windowDurationMins}` 为序列键，避免切换额度源后混合数据。每个历史点至少保存：

```js
{
  sourceId: "codex",
  windowDurationMins: 10080,
  usedPercent: 8,
  remainingPercent: 92,
  resetsAt: "2026-09-06T02:33:48.000Z",
  capturedAt: "2026-08-30T03:48:01.000Z"
}
```

历史文件增加 `schemaVersion`。旧版 `primary/secondary` 历史继续保留在文件中作为 `legacy` 数据，但不注入新的准确序列，因为旧记录没有足够信息判断原窗口时长。升级后的第一次有效刷新开始写入新序列。

现有显示偏好、窗口尺寸、Token 统计、价格缓存和模型用量账本保持原位。安装升级不得启用 `deleteAppDataOnUninstall`。

旧版 `last-quota-snapshot.json` 在读取时可根据其已有的 `windowDurationMins` 重新分类，因此离线启动也能把 10080 分钟的旧 `primary` 快照正确显示成 7 天额度。

## 右键快捷菜单

右键菜单改成单层，不包含任何 `submenu`：

1. 只读额度摘要，例如“主 Codex · 7 天剩余 92%”；
2. 显示/隐藏悬浮窗；
3. 刷新额度；
4. 悬浮窗置顶；
5. 打开额度统计；
6. 额度来源：主 Codex，点击后打开设置页的额度来源区；
7. 打开设置；
8. 切换语言；
9. 退出。

删除 `stickyToggleClick`、`keepToggleSubmenusOpen`、`findTraySubmenu` 及其坐标和延迟重开逻辑。原生菜单正常关闭是预期行为；需要连续调整的操作全部在设置页完成。

## 独立设置页

设置页使用单实例 `BrowserWindow`。重复打开时聚焦现有窗口，并可通过入口参数滚动到指定分区。关闭按钮默认隐藏窗口而不是销毁配置状态。

设置页包含四个分区：

### 额度与仪表

- 活动额度源选择；
- 当前源可用窗口摘要；
- 仪表数据来源及实际回退来源；
- 圆球或电池样式、电池方向；
- 自适应颜色与颜色联动方式。

### 窗口与卡片

- 置顶、磁吸、仪表左右位置；
- 总卡片开关和各卡片显示开关；
- 当前源没有对应窗口时，相关卡片选项禁用并解释原因；
- 重置卡片高度、左右布局和仪表尺寸。

### 统计与费用

- 历史统计卡、日历和 Token 费用卡；
- 统计项目显示与排序；
- 美元和人民币等值估算；
- 打开完整统计页。

### 关于与诊断

- 应用版本、用户套餐标签、活动额度源；
- 返回的额度源 ID、名称和窗口时长；
- 最后成功刷新时间和数据是否过期；
- 手动刷新；
- 复制脱敏诊断信息。

所有设置即时保存并通过现有通知通道实时更新悬浮窗。没有“应用”按钮。设置控件支持键盘焦点，禁用项提供文本原因。

## IPC 与安全边界

设置渲染页只能通过 `preload` 暴露的窄接口读取和更新白名单字段。主进程负责：

- 校验 `quotaSourceId` 是否来自当前服务端返回列表；
- 校验枚举、布尔值、尺寸和排序数组；
- 持久化显示偏好；
- 构造脱敏诊断文本；
- 创建、聚焦和定位设置窗口。

渲染页不能直接访问 Node.js、文件系统、认证目录或 App Server 进程。诊断文本不包含认证令牌、账户 ID、用户目录、完整本地路径或原始 JSON 响应。

## 刷新与错误处理

- 刷新成功：更新活动源、全部额度源摘要、历史和最后成功时间。
- 刷新失败且有缓存：继续显示最后有效数据，标记“数据已过期”，显示最后成功时间。
- 刷新失败且无缓存：显示“额度暂不可用”和可操作的重试入口。
- 活动源消失：回退到主 `codex` 并通知设置页。
- 未知窗口时长：展示实际时长，不进入 5 小时或 7 天统计。
- 套餐类型未知：显示“未知套餐”，不影响额度百分比。

## 测试策略

### 数据归一化测试

- Pro 主 `codex` 桶仅有 `primary: 10080`，应生成 `primary: null` 和有效 `secondary`。
- Spark 桶包含 300 和 10080，应同时生成 5 小时和 7 天窗口。
- `primary/secondary` 顺序颠倒时，分类结果保持不变。
- 多桶响应默认选择 `codex`，保存的有效来源优先，失效来源回退。
- 缺失百分比、未知时长和异常值不会生成虚假 `0%`。
- `usedPercent` 不受套餐倍率影响。

### 渲染与设置测试

- 缺少 5 小时窗口时自动隐藏对应卡片，仪表使用 7 天窗口。
- 切换到 Spark 后两张卡片出现，切回主 Codex 后恢复单卡布局。
- 设置即时持久化并在重启后恢复。
- 不可用卡片控制项被禁用并显示原因。
- 脱敏诊断内容不包含账户 ID、令牌或用户目录。

### 菜单测试

- 快捷菜单模板中不存在 `submenu`。
- 不再包含延迟重开和坐标定位函数。
- “额度来源”和“打开设置”能聚焦同一个设置窗口。
- 主窗口、统计窗口和托盘入口使用同一份快捷菜单行为。

### 回归与桌面验收

- 运行现有 `npm test` 全套测试。
- 构建 Windows NSIS 安装包。
- 保留现有 AppData 覆盖安装。
- 使用实际 Pro 账户验证主 Codex 7 天剩余量、Spark 切换、刷新失败缓存、右键快捷菜单和设置持久化。
- 退出并重新启动后再次核对额度源、窗口分类和设置窗口单实例行为。

## 完成标准

1. Pro 主 `codex` 的 10080 分钟窗口只显示为 7 天额度。
2. 不存在的 5 小时窗口不会显示为 `0%`、`--%` 卡片或错误仪表来源。
3. Spark 等独立桶可以在设置页选择且历史互不混合。
4. 右键菜单没有子菜单、没有闪动重开、没有坐标补丁。
5. 所有复杂配置可以在设置页连续调整并即时预览。
6. 现有用户数据在升级和覆盖安装后仍然存在。
7. 自动化测试、Windows 构建和真实 Pro 账户桌面验收全部通过。
