# 设置页、多屏吸附与初始化恢复设计

## 背景

当前版本已经具备首次运行初始化、Codex App Server 登录和磁吸窗口的基础能力，但三个边界场景仍然会互相放大问题：登录完成通知可能在等待器建立前到达；磁吸状态使用过期的显示器和整个屏幕 bounds，窗口在任务栏或负坐标屏幕上会被裁切；设置页只按视觉卡片分组，没有把“总开关—子开关—可用数据源”的关系表达清楚。

## 目标

1. 首次启动能够稳定完成 `initialize → initialized` 握手，并可靠捕获浏览器登录完成事件；失败时显示可重试、可诊断的状态，而不是卡在半初始化状态。
2. 磁吸展开窗口始终被约束在当前目标显示器的 `workArea` 内，支持负坐标、任务栏位于任意边、不同 DPI 和显示器切换；折叠状态仍保留可发现的边缘露出条。
3. 设置页按实际行为分组，清楚表达总开关和子开关依赖，禁用项不会误导用户，也不会因为重新渲染丢失已经保存的偏好。

## 设计决策

### 初始化与登录

- App Server 会话维护有界的最近通知缓存。通知先进入缓存，再唤醒当前等待器；等待器建立时先检查缓存，因此不会丢失早到的 `account/login/completed`。
- `account/login/completed` 的等待器在打开浏览器 URL 之前建立，作为第二层保护。
- 登录流程继续校验 URL 只允许 `chatgpt.com`、`auth.openai.com` 及其子域名；登录状态通过现有初始化控制器呈现为阶段、重试和错误信息。
- 额度刷新和首次初始化复用同一认证路径，避免两个流程各自维护不同的登录状态。

### 多屏磁吸

- 使用纯函数根据窗口 bounds、显示器 bounds/workArea 和记忆的 displayId 解析目标显示器。记忆的 displayId 只有在窗口中心或有效交集仍指向该显示器时才优先，否则按最大交集/中心距离恢复。
- 展开 bounds 统一经过约束：宽高不超过 workArea，x/y 被夹到 workArea 边界。所有吸附、重新锚定、启动恢复和底部右侧初始摆放都走同一约束。
- 重新锚定优先读取窗口当前实际 bounds，覆盖拖动跨屏、DPI 变化和显示器热插拔后的旧 displayId。
- 折叠 bounds 只把窗口主体移出工作区，保留 edge strip；展开 bounds 永远完整位于 workArea。

### 设置页

保留四个主标签，但在标签内按行为分组并显示说明：

- 额度：账户/数据源状态，悬浮窗卡片内容。
- 窗口：窗口行为、仪表外观、布局恢复。
- 统计：统计总开关、图表/日历、Token 与费用。
- 关于：诊断和版本信息。

依赖关系由一个纯函数集中计算，渲染层只负责将依赖映射到控件：

| 总开关/条件 | 受影响的控件 |
| --- | --- |
| `meterEnabled` | 仪表数据源、样式、方向、侧边模式 |
| `cardsMasterEnabled` + 数据源可用 | 主卡/次卡开关 |
| 主卡/次卡开关 | 对应卡片详情字段 |
| `adaptiveColorEnabled` | 颜色模式 |
| `tokenPanelEnabled` | Token 子项 |
| `quotaStatsPanelEnabled` | 图表、日历、Token 统计区域 |

渲染只改变控件的可用性和辅助说明，不覆盖用户已经保存的子偏好；重新打开设置页后依赖状态可重复计算。

## 验收标准

- 初始化测试覆盖：正常握手、通知早到、登录失败后重试、冷启动重试。
- 磁吸纯函数测试覆盖：负坐标、任务栏缩短 workArea、过大窗口、旧 displayId、跨屏移动；展开 bounds 完整包含于 workArea。
- 设置测试覆盖：四个标签仍可切换、依赖控件按预期禁用/恢复、不可用数据源不会启用对应卡片、页面无横向溢出。
- 在真实 Windows 进程中重新启动已安装版本，确认状态文件回到 ready；双屏/不同 DPI 场景下窗口不越过目标 workArea。
- 版本提升为 bugfix 版本并重新打包、覆盖安装；不执行 GitHub push 或 Release。
